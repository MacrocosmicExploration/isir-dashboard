ACTIVE EMPLOYEE MATCHING AND TEMPORARY SAVED ASSIGNMENTS

CURRENT APPROACH
The original SharePoint list stays unchanged. Reporter-based attribution is accepted
for this POC. The user is still in Transform Data; model relationships, measures
and visuals have not been completed. This guide supersedes the earlier proposal
to add snapshot columns to SharePoint.

Use a separate, values-only Excel workbook to keep incident assignments until the
future pipeline provides persistent storage. Power BI reads the workbook; it does
not write to it. Saving new assignments is a manual POC step. The extraction and
matching logic is automated; persistence is not yet scheduled or automatic.
Do not overwrite the saved table with a full freshly recomputed directory join.

MATCHING RULES
1. Keep only employee rows whose trimmed, case-insensitive EMPLOYEE_STATUS is Active.
   This filters directory eligibility, never the incident population.
2. Normalize email case and surrounding whitespace. Use an exact active match first.
3. Only when there are zero active exact matches, try the SAME local part under
   the alternate domain: tel.com <-> us.tel.com. Never strip domains generally.
4. Multiple active rows at the selected email remain ambiguous, even if identical.
   An ambiguous exact match does not fall through to the other domain.
5. Preserve every populated saved incident assignment. Current directory moves,
   inactive/departed employees and directory ambiguities do not erase it.
6. Missing/no-active/ambiguous matches stay unassigned and eligible for later review.
   Active is an eligibility rule, not a timestamp that ranks multiple active rows.

Email aliases are recorded as TEL domain alias. Review these proposed cases once
before saving: matching local parts are a controlled business assumption, not a
general proof of identity across domains. Exact active addresses take priority.
A current Active record represents the organization at directory extraction time,
not necessarily at an older incident's occurrence date.

C. VERIFY MATCHING BEFORE CAPTURE
Run the new ISIR_ReporterOrgSelfTest: 30 PASS expected. Refresh the preview and
validation. Source and preview rows must remain equal (178 at the known checkpoint).
Review Active exact email matches, Active TEL-domain alias matches, Ambiguous active

D. SAVE THE FIRST ASSIGNMENTS AS LITERAL VALUES
1. Open ISIR_ReporterOrgSnapshotAdditions. It contains eligible assignments for
   incidents whose saved assignment is blank. Note its row count.
2. At the current scale (at most 178 incidents), use the table menu in the upper-left
   of the Power Query preview > Copy Entire Table. Paste into a new Excel workbook
   as values, including the column headers. Check the pasted row count equals the
   additions query count. Preview copying is not a scalable full-data export; if
   the result exceeds the preview limit, use a full export instead.
3. Select the pasted range > Ctrl+T > My table has headers. Name the Excel table
   ISIR_OrgSnapshot under Table Design. Save as ISIR_OrgSnapshot.xlsx in approved
   corporate storage. Keep the file outside the source-code repository.
4. Retain the SourceItemID column as whole numbers, DirectoryExtractDate as a date,
   and CapturedAtUTC as text (ISO UTC with Z). Keep both email columns as text.
   CapturedAtUTC records when the proposal was generated, not the workbook save time.
5. In stg_ISIR_OrgSnapshot_Raw Advanced Editor, replace only the empty value of
   SnapshotFilePath with the workbook's full local or network path. M uses literal
   backslashes, e.g. SnapshotFilePath = "C:\Work\ISIR\ISIR_OrgSnapshot.xlsx"
   (Use your actual path with normal single backslashes in the M string.)
   The query reads the named Excel TABLE, not a worksheet or suggested range.
   Close the Excel workbook after saving, then refresh the staging query.
6. Refresh ISIR_ReporterOrgPreview and ISIR_ReporterOrgValidation. For an unchanged
   source and directory, Existing snapshots kept must equal the saved row count,
   and New proposed fills should be zero. Unresolved incidents stay in the source.
   This verifies persistence; passing matching self-tests alone does not.

If there are zero eligible additions, do not manufacture assignments. An empty
snapshot remains valid while unresolved matches are investigated.
The snapshot workbook is tied to this single ISIR source. SourceItemID is its
incident key, not email. Preserve those IDs during pipeline migration; introduce
a source namespace if combining multiple source systems with overlapping IDs.

E. FUTURE CAPTURES DURING THE POC
After updating source data or the employee extract, refresh and review the additions.
Back up the saved workbook before editing. Append only previously absent SourceItemID
values. If a row with that ID exists but its subsidiary is blank, fill that row after
review; do not append a duplicate. Never replace nonblank assignments automatically.
An exact duplicate key makes the query fail visibly rather than choosing a row.
Retain older saved rows even if they are temporarily absent from the source report.
Save, refresh, and check that the corresponding proposals disappear. Power BI never
writes these changes itself. The future pipeline can replace this manual capture
with an idempotent insert/fill-only operation using the same incident key and columns.
A deliberate correction of an incorrect saved assignment should be documented.

Once the current matching tests pass and snapshot read-back reconciles, Close & Apply.
In Model view, remove unintended auto-created links among these four tables and add:

DimCategory[CategoryKey] (1) -> FactIncident[CategoryKey] (*)
DimReporterSubsidiary[ReporterSubsidiaryKey] (1) -> FactIncident[ReporterSubsidiaryKey] (*)
All active, Single direction from dimension to fact. No employee-table relationship
and no active SubmittedDate relationship are required.
Then follow docs/model-setup.txt for date-table marking, sort columns, measures and
QA cards. Total incidents remains 178 at the source checkpoint; category/asset/date
counts remain as previously supplied. Subsidiary bars must sum to all incidents,
including Unassigned. Do not infer geography or exclude incidents from prefix names.
